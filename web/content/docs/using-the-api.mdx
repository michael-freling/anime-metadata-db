---
title: Using the API
description: Query the hosted read-only Connect service with a plain HTTP POST and JSON.
---


The dataset is served read-only by a [Connect RPC](https://connectrpc.com)
service. You can call it with an ordinary HTTP `POST` and a JSON body — no client
library or codegen required.

## Your first call

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetStats \
  -H 'Content-Type: application/json' -d '{}'
```

```json
{"version":"<commit>","stats":{"franchises":1,"series":152,"seasons":222,"episodes":3229,
 "characters":647,"staff":445,"earliestReleaseYear":2006,"latestReleaseYear":2026}}
```

That's the whole contract: `POST` a JSON body to
`/{package}.{Service}/{Method}`, get JSON back.

## Endpoint

```
POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/{Method}
Content-Type: application/json
```

`https://anime-metadata-db.vercel.app` is the hosted public instance. To run your
own, start the server locally (`cd api && go run ./cmd/api`, see
[Building the dataset](/docs/building-the-dataset)) and use
`http://localhost:8080` instead — the paths are identical.

## Methods

The **[API reference](/docs/api)** documents every method: its request and
response fields, their types, and the descriptions from the schema — with a
playground on each page that sends a real request to the deployed service and
shows you what comes back.

It is generated from
[`anime.proto`](https://github.com/michael-freling/anime-metadata-db/blob/main/api/proto/anime/v1/anime.proto),
the same schema the server and this site's own client are built from, so it
cannot drift from the API it describes. There is no separate list to keep in
step: a method added to the service appears there, and a field renamed there
cannot be described by the old name here.

Some behaviour is worth knowing before you start.

`ListCatalog` is the browse entry point and the cheapest way to ask what the
dataset contains, because it does not nest the structure. `ListFranchises`
returns only multi-series **franchises**; a standalone series is reachable
through `Search` and `GetSeries`. For `Search`, a blank `query` matches nothing.
An unknown `seriesId` is a `not_found` error rather than an empty list, so a
typo is not mistaken for a series with no cast.

## Nothing comes back unbounded

This dataset is built to hold the full upstream catalogue, so **no response ever
returns a whole collection**. Every one takes one of two shapes.

**Lists page.** Send `limit` and, to continue, the `pageToken` you were given:

```json
{"pageToken": "bzoyNA", "limit": 20}
```

and you get back `nextPageToken` — empty on the last page — plus `totalSize`,
the count of every match rather than of the page. `limit` defaults to 100 (50
for `Search`). Treat `pageToken` as opaque: it is deliberately not a documented
format, so that the cursor scheme can change without breaking you. A token you
did not receive from us is an `invalid_argument` error rather than a silent
first page.

**A `Get*` response embeds at most the first 25 of each collection**, as a
convenience, and tells you the real count beside it:

```jsonc
{
  "series": {
    "id": "tensei-shitara-slime-datta-ken",
    "characters": [ /* 25 of them */ ],
    "charactersTotal": 148,          // ← what actually exists
    "seasons": [ /* … */ ],
    "seasonsTotal": 5
  }
}
```

Read the `*Total`, never the array length, whenever you show a count — the array
is a page. To get the rest, page the matching list method: `ListCharacters` for
a cast, `ListWorks` or `ListEpisodes` for releases and episodes,
`ListAppearances`, `ListCredits`, `ListSeries`.

## Examples

Search — case-insensitive substring over titles:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/Search \
  -H 'Content-Type: application/json' -d '{"query": "demon", "limit": 5}'
```

```json
{"results":[{"kind":"SERIES","id":"demon-slayer","title":"Demon Slayer"}]}
```

Fetch one series — the `id` comes from a search result. Each collection below
is the first page of itself, with its true size alongside:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetSeries \
  -H 'Content-Type: application/json' -d '{"id": "demon-slayer"}'
```

```json
{
  "series": {
    "id": "demon-slayer",
    "title": "Demon Slayer",
    "seasons": [
      {
        "id": "demon-slayer-s1",
        "number": 1,
        "releaseYear": 2019,
        "releaseSeason": "SPRING",
        "externalIds": {"anilistId": 101922, "anidbId": 14107, "tvdbId": 348545},
        "episodes": [
          {"absoluteNumber": 1, "airedNumber": 1},
          {"absoluteNumber": 2, "airedNumber": 2}
        ]
      }
    ],
    "movies": [
      {"id": "demon-slayer-mugen-train-film", "title": "Mugen Train", "releaseYear": 2020}
    ]
  }
}
```

A `Franchise` nests `series`, which nests `seasons`, `movies` and `specials`,
each carrying `episodes`. Field names in the JSON are camelCase (`releaseYear`,
`externalIds`, `absoluteNumber`). See [Using the dataset](/docs/using-the-dataset)
for the full model.

Two things the schema offers that no response currently carries: `releaseDate`
(a `YYYY-MM-DD` string when set — a release is dated only to `releaseYear` and
`releaseSeason` today) and `externalIds.tmdbId`. `externalIds` cross-maps to
AniList, AniDB, TVDB and — for characters and staff — Wikidata. Episodes carry
numbering only: no title, no date. See [Sources and licensing](/docs/sources-and-licensing)
for the full list of what the build never fills, and why.

Titles resolve per request. Ask in the language a title was written in and you
get the native script; ask in any other and you get an English title where the
dataset has one and the romanization otherwise — so an English request answers
`Kami no Shizuku` rather than `神の雫`, readable without claiming to be an
English title. Most of the catalogue has no English title at all.

"The language a title was written in" is usually Japanese, but not always, and
the rule follows the title rather than the request: `Accept-Language: ko` on
`metal-cardbot-w` answers `메탈카드봇W`, while a Japanese reader asking for the
same series gets `Metal Cardbot W`, being no better served by Hangul than an
English reader would be.

`Accept-Language: *` returns every language instead, each under its own tag:
`en` for an English title, `ja-Latn` (or `ko-Latn`, …) for a romanization.

## Characters and staff

Characters and staff are **global** nodes, not children of a series. A character
attaches onto the structure through its `appearances`, so the same node is
reachable three ways — nested in a series' `characters`, by id from
`GetCharacter`, and as a credit from `GetStaff` — and it names the series it
appears in, with `appearancesTotal` giving the full count and `ListAppearances`
paging beyond the first:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetCharacter \
  -H 'Content-Type: application/json' -d '{"id": "artoria-pendragon"}'
```

```json
{
  "character": {
    "id": "artoria-pendragon",
    "externalIds": {"wikidataId": "Q4918886"},
    "voiceActors": [
      {"staffId": "ayako-kawasumi", "language": "ja"}
    ],
    "appearances": [
      {"seriesId": "fate-stay-night"},
      {"seriesId": "fate-zero"}
    ]
  }
}
```

That response has no `name` or `staffName`, and it is not a bug: names are
filled from Wikidata **at build time**, and the committed dataset was built
without the Wikidata fetch. Run `builder init` before `builder build` and the
same call returns `"name": "Artoria Pendragon"` on the character and
`"staffName": "Ayako Kawasumi"` on each voice-actor link. Every other field is
independent of it, so the graph is fully usable by id either way.

`voiceActors` on the character is the cast that **holds throughout** — an
original-language role is nearly always the same person in every adaptation.
Cast that varies by series is not there: English dubs are routinely recast, so
each of those lives on the appearance it was cast in, optionally with a `scope`
narrowing it to specific seasons, movies or specials.

You never have to combine the two yourself. An appearance's `voiceActors` is
already **the cast for that appearance** — the constant cast plus whoever is
specific to it — and `ListCharacters` with a `seriesId` (and the cast embedded
in `GetSeries`) resolves each character's `voiceActors` the same way. Only an
unscoped character listing reports the constant cast alone, because no series
was named to be specific to. Each link repeats the staff member's resolved
`staffName`, so rendering a cast list needs no second call.

Because those lists are resolved, an actor who voices the character everywhere
appears in every one of them. `throughout` says so: it marks the credits that
came from the character rather than from the thing being described. Ignore it
and you still have the full cast; read it and you can show what a series adds
— *"Fate/Zero — also Kari Wahlgren"* — without restating Ayako Kawasumi on
every row. It is set only where a list mixes the two, so an unscoped
character's own `voiceActors` carries no marks at all.

Saber is the worked example: Ayako Kawasumi voices her in every Fate work and
sits on the character, while Kate Higgins and Kari Wahlgren sit on the
appearances they were cast in. Asking for Fate/Zero's cast returns Kawasumi and
Wahlgren, and never Higgins.

An appearance can be narrower than a whole series. Higgins dubbed the 2006
*Fate/stay night* only, not the 2014 re-adaptation the same series id also
holds, so her appearance carries a `scope` naming that season — and Saber holds
a second appearance, for the other installments, with no English cast. An
appearance is therefore identified by its `seriesId` **and** its `scope`, and
each scope entry carries the installment's resolved `title` (plus `number` for a
season, which usually has no title of its own) so you can label it without a
second call.

**Two different things are called a language here**, and mistaking one for the
other is the first thing most people do.

`ListStaff`'s `language` field is a **filter**: it picks *which people* come
back — those credited in that language. `Accept-Language` is **rendering**: it
picks what language their names are written in. Neither implies the other, and
`totalSize` is where you can see it: asking for Japanese names returns all 445
staff, while filtering to the Japanese-credited cast returns 394 of them.

So the filter alone answers with the Japanese cast under their English names,
because no `Accept-Language` was sent and English is the default:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/ListStaff \
  -H 'Content-Type: application/json' -d '{"language": "ja", "limit": 2}'
```

```json
{"staff":[{"id":"ayako-kawasumi", "name":"Ayako Kawasumi", "externalIds":{"wikidataId":"Q49566"}}, {"id":"natsuki-hanae", "name":"Natsuki Hanae", "externalIds":{"wikidataId":"Q2596113"}}], "nextPageToken":"bzoy", "totalSize":394}
```

Send both to get the same people under their Japanese names:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/ListStaff \
  -H 'Content-Type: application/json' -H 'Accept-Language: ja' \
  -d '{"language": "ja", "limit": 2}'
```

```json
{"staff":[{"id":"ayako-kawasumi", "name":"川澄綾子", "externalIds":{"wikidataId":"Q49566"}}, {"id":"natsuki-hanae", "name":"花江夏樹", "externalIds":{"wikidataId":"Q2596113"}}], "nextPageToken":"bzoy", "totalSize":394}
```

Keeping them apart is what lets a Japanese reader browse the *whole* cast in
Japanese. The header alone does that — English-dub actors included, under the
names they are credited by, because `アーロン・ロバーツ` is a spelling of his
name rather than a fact anyone recorded:

```json
{"staff":[{"id":"aaron-roberts", "name":"Aaron Roberts", "externalIds":{"wikidataId":"Q141031024"}}, {"id":"annie-wild", "name":"Annie Wild", "externalIds":{"wikidataId":"Q134440355"}}], "nextPageToken":"bzoy", "totalSize":445}
```

An English-language actor's `name` follows the same rule, so an
`Accept-Language: ja` request answers `ザック・アギラール` for Zach Aguilar —
that is how a Japanese reader sees his name. The dataset stores the name
itself as the `original` and the katakana as the `ja` translation, so reading
`data/` directly gives you both.

`GetStaff` is the inverse — the characters a person is cast as, with the
language and the series each casting covers:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetStaff \
  -H 'Content-Type: application/json' -d '{"id": "ayako-kawasumi"}'
```

```json
{
  "staff": {"id": "ayako-kawasumi", "externalIds": {"wikidataId": "Q49566"}},
  "credits": [
    {
      "characterId": "artoria-pendragon",
      "language": "ja",
      "seriesIds": ["fate-stay-night", "fate-zero"]
    }
  ]
}
```

One credit is emitted per character and language, listing every series the
casting covers — so a voice actor who plays the same character across a whole
franchise appears once, not once per series.

Names follow the same `Accept-Language` rules as titles, via `name` and (with
`Accept-Language: *`) `localizedName`.

Only **facts** are served: ids, names, and the appearance and voice-actor graph.
Roles, biographies and images are deliberately absent; fetch those live from the
external ids.

## Localized titles

Every title-bearing node returns a single `title` string, resolved from the
request's `Accept-Language` header (default `en`). For each title, resolution
tries, in order:

1. the requested language,
2. for a non-English request, the native `original`,
3. English,
4. the native `original`,
5. any available translation.

```sh
# Japanese titles where available, else the native original → "鬼滅の刃":
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetSeries \
  -H 'Content-Type: application/json' -H 'Accept-Language: ja' \
  -d '{"id": "demon-slayer"}'
```

Send `Accept-Language: *` to additionally receive the full `localizedTitle` (the
native `original` plus every translation) on every node.

> **Scope.** The API serves the structural catalog — franchises, series,
> seasons, movies, specials and episodes. Characters and staff are present in the
> committed dataset but not yet exposed over the API.
