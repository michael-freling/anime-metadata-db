title: Using the API
description: Query the hosted read-only Connect service with a plain HTTP POST and JSON.
---


The dataset is served read-only by a [Connect RPC](https://connectrpc.com)
service. You can call it with an ordinary HTTP `POST` and a JSON body — no client
library or codegen required.

## Your first call

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetHealth \
  -H 'Content-Type: application/json' -d '{}'
```

```json
{"status":"ok","version":"<commit>","stats":{"franchises":1,"series":3,"seasons":9,"episodes":124}}
```

That's the whole contract: `POST` a JSON body to
`/{package}.{Service}/{Method}`, get JSON back.

## Endpoint

```
POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/{Method}
Content-Type: application/json
```

`https://anime-metadata-db.vercel.app` is the hosted public instance. To run your
own, start the server locally (`cd api && go run ./cmd/api`, see
[Building the dataset](/docs/building-the-dataset)) and use
`http://localhost:8080` instead — the paths are identical.

## Methods

| Method | Body | Returns |
|---|---|---|
| `GetHealth` | `{}` | liveness, build version, dataset stats |
| `ListCatalog` | `{"limit": 20}` | every top-level entry as a flat summary |
| `Search` | `{"query": "...", "limit": 10}` | matching franchises and series |
| `ListWorks` | `{"releaseYear": 2026, "limit": 20}` | individual releases, by year, quarter, kind or series |
| `ListFranchises` | `{"limit": 10}` | multi-series franchises, nested |
| `GetFranchise` | `{"id": "..."}` | one franchise |
| `ListSeries` | `{"franchiseId": "...", "limit": 10}` | one franchise's series |
| `GetSeries` | `{"id": "..."}` | one series (standalone or under a franchise) |
| `ListEpisodes` | `{"seasonId": "...", "limit": 20}` | the episodes of one season or special |
| `GetCharacter` | `{"id": "..."}` | one character with its cast |
| `ListCharacters` | `{"seriesId": "...", "limit": 10}` | the cast of one series, or of everything |
| `ListAppearances` | `{"characterId": "...", "limit": 10}` | the series one character appears in |
| `GetStaff` | `{"id": "..."}` | one staff member |
| `ListStaff` | `{"language": "ja", "limit": 10}` | staff, optionally by credited language |
| `ListCredits` | `{"staffId": "...", "limit": 10}` | the roles one staff member is cast in |

`ListFranchises` returns only multi-series **franchises**; a standalone series is
reachable through `Search` and `GetSeries`. `ListCatalog` is the cheaper way to
ask what the dataset contains, because it does not nest the structure. For
`Search`, a blank `query` matches nothing. An unknown `seriesId` is a
`not_found` error rather than an empty list, so a typo is not mistaken for a
series with no cast.

## Nothing comes back unbounded

This dataset is built to hold the full upstream catalogue, so **no response ever
returns a whole collection**. Every one takes one of two shapes.

**Lists page.** Send `limit` and, to continue, the `pageToken` you were given:

```json
{"pageToken": "bzoyNA", "limit": 20}
```

and you get back `nextPageToken` — empty on the last page — plus `totalSize`,
the count of every match rather than of the page. `limit` defaults to 100 (50
for `Search`). Treat `pageToken` as opaque: it is deliberately not a documented
format, so that the cursor scheme can change without breaking you. A token you
did not receive from us is an `invalid_argument` error rather than a silent
first page.

**A `Get*` response embeds at most the first 25 of each collection**, as a
convenience, and tells you the real count beside it:

```jsonc
{
  "series": {
    "id": "tensei-shitara-slime-datta-ken",
    "characters": [ /* 25 of them */ ],
    "charactersTotal": 148,          // ← what actually exists
    "seasons": [ /* … */ ],
    "seasonsTotal": 5
  }
}
```

Read the `*Total`, never the array length, whenever you show a count — the array
is a page. To get the rest, page the matching list method: `ListCharacters` for
a cast, `ListWorks` or `ListEpisodes` for releases and episodes,
`ListAppearances`, `ListCredits`, `ListSeries`.

## Examples

Search — case-insensitive substring over titles:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/Search \
  -H 'Content-Type: application/json' -d '{"query": "demon", "limit": 5}'
```

```json
{"results":[{"kind":"ENTRY_KIND_SERIES","id":"demon-slayer","title":"Demon Slayer"}]}
```

Fetch one series — the `id` comes from a search result. Each collection below
is the first page of itself, with its true size alongside:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetSeries \
  -H 'Content-Type: application/json' -d '{"id": "demon-slayer"}'
```

```json
{
  "series": {
    "id": "demon-slayer",
    "title": "Demon Slayer",
    "seasons": [
      {
        "id": "demon-slayer-s1",
        "number": 1,
        "releaseYear": 2019,
        "releaseSeason": "RELEASE_SEASON_SPRING",
        "externalIds": {"anilistId": 101922, "anidbId": 14107, "tvdbId": 348545},
        "episodes": [
          {"absoluteNumber": 1, "airedNumber": 1},
          {"absoluteNumber": 2, "airedNumber": 2}
        ]
      }
    ],
    "movies": [
      {"id": "demon-slayer-mugen-train-film", "title": "Mugen Train", "releaseYear": 2020}
    ]
  }
}
```

A `Franchise` nests `series`, which nests `seasons`, `movies` and `specials`,
each carrying `episodes`. Dates are `YYYY-MM-DD` strings; `externalIds`
cross-maps each node to AniList, AniDB, TMDB, TVDB and Wikidata. Field names in
the JSON are camelCase (`releaseYear`, `externalIds`, `absoluteNumber`). See
[Using the dataset](/docs/using-the-dataset) for the full model.

## Characters and staff

Characters and staff are **global** nodes, not children of a series. A character
attaches onto the structure through its `appearances`, so the same node is
reachable three ways — nested in a series' `characters`, by id from
`GetCharacter`, and as a credit from `GetStaff` — and it names the series it
appears in, with `appearancesTotal` giving the full count and `ListAppearances`
paging beyond the first:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetCharacter \
  -H 'Content-Type: application/json' -d '{"id": "artoria-pendragon"}'
```

```json
{
  "character": {
    "id": "artoria-pendragon",
    "externalIds": {"wikidataId": "Q4918886"},
    "voiceActors": [
      {"staffId": "ayako-kawasumi", "language": "ja"}
    ],
    "appearances": [
      {"seriesId": "fate-stay-night"},
      {"seriesId": "fate-zero"}
    ]
  }
}
```

That response has no `name` or `staffName`, and it is not a bug: names are
filled from Wikidata **at build time**, and the committed dataset was built
without the Wikidata fetch. Run `builder init` before `builder build` and the
same call returns `"name": "Artoria Pendragon"` on the character and
`"staffName": "Ayako Kawasumi"` on each voice-actor link. Every other field is
independent of it, so the graph is fully usable by id either way.

`voiceActors` on the character is the cast that **holds throughout** — an
original-language role is nearly always the same person in every adaptation.
Cast that varies by series is not there: English dubs are routinely recast, so
each of those lives on the appearance it was cast in, optionally with a `scope`
narrowing it to specific seasons, movies or specials.

You never have to combine the two yourself. An appearance's `voiceActors` is
already **the cast for that series** — the constant cast plus whoever is
specific to it — and `ListCharacters` with a `seriesId` (and the cast embedded
in `GetSeries`) resolves each character's `voiceActors` the same way. Only an
unscoped character listing reports the constant cast alone, because no series
was named to be specific to. Each link repeats the staff member's resolved
`staffName`, so rendering a cast list needs no second call.

Saber is the worked example: Ayako Kawasumi voices her in every Fate work and
sits on the character, while Kate Higgins (Fate/stay night) and Kari Wahlgren
(Fate/Zero) sit on their appearances. Asking for Fate/Zero's cast returns
Kawasumi and Wahlgren, and never Higgins.

`GetStaff` is the inverse — the characters a person is cast as, with the
language and the series each casting covers:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetStaff \
  -H 'Content-Type: application/json' -d '{"id": "ayako-kawasumi"}'
```

```json
{
  "staff": {"id": "ayako-kawasumi", "externalIds": {"wikidataId": "Q49566"}},
  "credits": [
    {
      "characterId": "artoria-pendragon",
      "language": "ja",
      "seriesIds": ["fate-stay-night", "fate-zero"]
    }
  ]
}
```

One credit is emitted per character and language, listing every series the
casting covers — so a voice actor who plays the same character across a whole
franchise appears once, not once per series.

Names follow the same `Accept-Language` rules as titles, via `name` and (with
`Accept-Language: *`) `localizedName`.

Only **facts** are served: ids, names, and the appearance and voice-actor graph.
Roles, biographies and images are deliberately absent; fetch those live from the
external ids.

## Localized titles

Every title-bearing node returns a single `title` string, resolved from the
request's `Accept-Language` header (default `en`). For each title, resolution
tries, in order:

1. the requested language,
2. for a non-English request, the native `original`,
3. English,
4. the native `original`,
5. any available translation.

```sh
# Japanese titles where available, else the native original → "鬼滅の刃":
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetSeries \
  -H 'Content-Type: application/json' -H 'Accept-Language: ja' \
  -d '{"id": "demon-slayer"}'
```

Send `Accept-Language: *` to additionally receive the full `localizedTitle` (the
native `original` plus every translation) on every node.

> **Scope.** The API serves the structural catalog — franchises, series,
> seasons, movies, specials and episodes. Characters and staff are present in the
> committed dataset but not yet exposed over the API.
