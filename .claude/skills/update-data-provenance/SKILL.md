# Update data provenance

`docs/content/docs/sources-and-licensing.md` states, per field, which upstream
source fills it and under which licence. `NOTICE` credits each source and is the
file that legally travels with any redistribution. Both were written by reading
`internal/build` — so both go stale the moment the builder changes, and neither
has a compiler to catch it.

Stale provenance is not a documentation nit. Under-crediting a source is an
attribution failure, and over-crediting one (claiming an upstream supplied
something the project actually authored) misrepresents what a consumer is free
to take. Treat a discrepancy here the way you would a failing test.

## 1. Run the mechanical checks

From the repository root:

```bash
node .claude/skills/update-data-provenance/scripts/check-provenance.mjs
```

It fails (exit 1) on the two drifts that are purely structural:

- a field in `config/schemas/*.json` with no row in the provenance table
- a URL in `config.yaml` whose source is not credited in `NOTICE`

It also prints the builder fill sites you need for step 2, and the `$defs` the
table deliberately documents as a single row.

A pass here means **nothing is missing**. It does not mean the existing rows are
still true — the script cannot tell which source fills a field.

## 2. Verify the "filled from" column against the builder

This is the part that cannot be automated, and the part that was wrong the last
two times it was checked. For every row of the table, read the code and confirm
the claim:

- `internal/build/build.go` — `fillTitles`, `fillReleaseSeason`,
  `fillExternalIDs`, `assignAbsoluteNumbers`, and the per-node `fillSeason` /
  `fillMovie` / `fillSpecial`
- `internal/build/titles.go` — `inferTitle`, which decides what becomes
  `original` vs. the `en` / `ja` translations
- `internal/build/characters.go` — `fillNames`, the only place Wikidata data
  enters the dataset
- `internal/sources/{offlinedb,animelists,wikidata}` — what each adapter
  actually parses out of its upstream

Rules that have caught real errors:

- **Distinguish sourced from researched.** A field is only attributable to a
  source if the builder *reads it from* that source. Cast structure that was
  looked up on Wikidata by hand and typed into `config/overrides/` is the
  project's own editorial work, and crediting Wikidata for it overstates what
  is CC0.
- **Distinguish a value from a count.** `episodes[].airedNumber` is generated by
  expanding anime-offline-database's episode *count* to 1…n. Upstream supplies
  no per-episode records.
- **State the authored-wins rule.** The builder only fills a field the override
  left empty and merges per field, so every upstream-filled row is conditional.
  Keep that stated once, near the table.
- **Never guess a licence from a repository being public.** If an upstream
  states no licence, say so plainly and say what the project takes from it,
  as the Anime-Lists section does.

## 3. Reconcile the four places provenance is written

They must agree. In order of how much a mistake costs:

| File | Why it matters |
|---|---|
| `NOTICE` | Ships with every redistribution. Must credit each source and claim no more than it supplied. |
| `LICENSE-DATA` | States the outbound licence and why. Only change if the *licence stack* changed, not for wording. |
| `docs/content/docs/sources-and-licensing.md` | The detailed, field-level explanation. |
| `README.md` licensing section | Summary table only; keep consistent with `LICENSE-DATA`. |

Note that `README.md` and `docs/content/docs/using-the-api.md` also mention the
appearance and voice-actor graph when describing *what the dataset stores* under
the facts-not-expression rule. That is a different claim from provenance and is
correct as written — do not "fix" it to match `NOTICE`.

## 4. If a source was added or removed

Adding a source can change the outbound licence of `data/`, so this needs more
than a new table row:

1. Find its licence. Record it verbatim in `NOTICE` with a link.
2. Check compatibility. `data/` is published under ODbL + DbCL because
   anime-offline-database's share-alike reaches derivative databases. A new
   source that is CC0, public domain, or bare factual identifiers is absorbed
   without changing anything. A new source under a *different* share-alike or a
   non-commercial or attribution-with-conditions licence may be incompatible —
   stop and raise it rather than quietly adding rows.
3. If the outbound licence has to change, `LICENSE-DATA`, `README.md`, the docs
   page and `NOTICE` all change together.
4. Removing a source does not automatically relax the outbound licence: the
   existing `data/` may still be a derivative of it. Say so rather than
   assuming a rebuild launders it.

## 5. Confirm

Re-run the script, and build the docs so the page still renders:

```bash
node .claude/skills/update-data-provenance/scripts/check-provenance.mjs && make build
```

If you changed the script itself, run its own tests too — they exist because
two false negatives shipped past manual verification:

```bash
node --test .claude/skills/update-data-provenance/scripts/check-provenance.test.mjs
```

Report which rows you changed and which you verified as still correct. "Verified
against `internal/build`" means you read it — not that the script passed.

## Notes

- Fields are matched **qualified by their container** (`seasons[].part`, not
  `part`), so a name documented under one container cannot vouch for an
  undocumented field of the same name under another. Write the container in the
  table's first column or the field reads as missing.
- A `$def` reached from several parents is qualified by each of them, because
  what fills it can differ by parent — `seasons[].externalIds.anidbId` comes
  from anime-offline-database while `characters[].externalIds.anidbId` is never
  filled at all. Writing `*.field` asserts the opposite: that it is filled the
  same way under every container. Use the wildcard only when that is true; the
  script cannot check it for you.
- A property pointing at a record whose own fields are documented individually
  (`series.seasons`, `season.externalIds`) is structure, not data, and needs no
  row. The script lists what it skipped on that basis.
- The script's `OPAQUE_DEFS` list encodes a claim: every field inside those
  `$defs` shares one provenance, so the table covers each with a single row. If
  you add a field to one of them that comes from somewhere else, remove the def
  from that list and enumerate its fields — no check will catch it for you.
- The `$defs` names in `SCALAR_DEFS` and `OPAQUE_DEFS` are matched literally. If
  a schema `$def` is renamed, update the script or its checks silently narrow.
- Exit 2 means the script could not run its comparison — a renamed
  `## Where each field comes from` heading, malformed JSON, or a `config.yaml`
  with no source URLs. It never exits 0 without having compared something.
