title: Using the API
description: Query the hosted read-only Connect service with a plain HTTP POST and JSON.
---


The dataset is served read-only by a [Connect RPC](https://connectrpc.com)
service. You can call it with an ordinary HTTP `POST` and a JSON body — no client
library or codegen required.

## Your first call

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/SearchSeries \
  -H 'Content-Type: application/json' -d '{"query": "demon", "limit": 3}'
```

```json
{"series":[{"id":"demon-slayer","title":"Demon Slayer","firstReleaseYear":2019,
 "latestReleaseYear":2025,"works":7,"episodes":63}],"totalSize":2}
```

That's the whole contract: `POST` a JSON body to
`/{package}.{Service}/{Method}`, get JSON back.

## Endpoint

```
POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/{Method}
Content-Type: application/json
```

`https://anime-metadata-db.vercel.app` is the hosted public instance. To run your
own, start the server locally (`cd api && go run ./cmd/api`, see
[Building the dataset](/docs/building-the-dataset)) and use
`http://localhost:8080` instead — the paths are identical.

## Three methods

That is the whole API. It is small on purpose: a small surface is one you can
hold in your head, and one we can keep stable.

| Method | Answers |
|---|---|
| [`SearchSeries`](/docs/api/search-series) | "which series are called *demon*?" |
| [`SearchReleases`](/docs/api/search-releases) | "what premiered in Winter 2026?" |
| [`GetSeries`](/docs/api/get-series) | "tell me everything about this series" |

**Series and releases are searched separately because they are different
things.** A series spans years and has no quarter, so `Winter 2026` cannot
select one — it selects the seasons, films and specials that premiered then,
each of which names the series it belongs to. Take a `seriesId` from a release
and pass it to `GetSeries` to go from one to the other.

The **[API reference](/docs/api)** documents each method: its request and
response fields, their types, and the descriptions from the schema — with a
playground on each page that sends a real request to the deployed service and
shows you what comes back.

It is generated from
[`anime.proto`](https://github.com/michael-freling/anime-metadata-db/blob/main/api/proto/anime/v1/anime.proto),
the same schema the server and this site's own client are built from, so it
cannot drift from the API it describes.

> **Other methods you may see on the wire.** The site you are reading also calls
> a second service, `browse.v1.BrowseService`, for things only a browse UI needs
> — the franchise grouping, flat catalog rows, global character and staff
> indexes. It is deliberately undocumented and carries **no compatibility
> promise**: it changes whenever these pages do. Build against `anime.v1`.

## What paginates, and what does not

## Nothing comes back unbounded

The rule is per shape, and there are only two shapes.

**Searches page.** `SearchSeries` and `SearchReleases` both take `limit` and a
`pageToken`, and both return `nextPageToken` — empty on the last page — plus
`totalSize`, the count of every match rather than of the page:

```json
{"pageToken": "bzoyNA", "limit": 20}
```

`limit` defaults to 50. Treat `pageToken` as opaque: it is deliberately not a
documented format, so the cursor scheme can change without breaking you. A token
you did not receive from us is an `invalid_argument` error rather than a silent
first page. This is the half that has to page — the catalogue grows.

**`GetSeries` returns a series whole.** Every season with every episode, every
film, every special, and the whole cast with voice actors resolved. No caps, no
`*Total` fields to read instead of an array length, no second call:

```jsonc
{
  "series": {
    "id": "tensei-shitara-slime-datta-ken",
    "seasons": [ /* 5, carrying 96 episodes between them */ ],
    "characters": [ /* all 148 */ ]
  },
  "franchiseId": ""
}
```

That is bounded by what one series can be rather than by how large the catalogue
grows, which is why it is safe to send in full. The largest series in the
dataset today answers in **66 KB**; the one with the longest run — 171 episodes
— answers in 12 KB. An array's length is the count.

`franchiseId` names the brand a series belongs to, or is empty when it stands
alone. It is a grouping key and nothing more: two series carrying the same one
belong together. There is no franchise method to dereference it with.

## Examples

Search series — case-insensitive substring over titles, in any language. Each
hit carries the aggregates a result row needs, so listing results opens no
further calls:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/SearchSeries \
  -H 'Content-Type: application/json' -d '{"query": "demon", "limit": 3}'
```

```json
{"series":[{"id":"demon-slayer","title":"Demon Slayer","firstReleaseYear":2019,
 "latestReleaseYear":2025,"works":7,"episodes":63}],"totalSize":2}
```

Search releases — a seasonal chart is this call. Each row names its series, so
nothing has to be looked up to render it:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/SearchReleases \
  -H 'Content-Type: application/json' -d '{"releaseYear": 2026, "releaseSeason": "WINTER", "limit": 1}'
```

```json
{"releases":[{"kind":"TV_SEASON","id":"29-sai-dokushin-chuuken-boukensha-no-nichijou-s1",
 "seriesId":"29-sai-dokushin-chuuken-boukensha-no-nichijou",
 "seriesTitle":"An Adventurer's Daily Grind at Age 29","number":1,"releaseYear":2026,
 "releaseSeason":"WINTER","episodeCount":12,
 "externalIds":{"anilistId":192261,"anidbId":19324,"tvdbId":463334}}],
 "nextPageToken":"bzoy","totalSize":80}
```

All three filters — `query`, `releaseYear`, `releaseSeason` — are optional and
combine freely. The one request that is refused is a quarter with no year:

```json
{"code":"invalid_argument","message":"release_season requires release_year: a quarter alone spans every year in the dataset"}
```

"Winter" across every year the dataset covers is not a question anyone means to
ask, and answering it would look like a filter that worked.

Fetch one series — the `id` comes from a search result, or from a release's
`seriesId`. Everything under it comes back:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetSeries \
  -H 'Content-Type: application/json' -d '{"id": "demon-slayer"}'
```

```json
{
  "series": {
    "id": "demon-slayer",
    "title": "Demon Slayer",
    "seasons": [
      {
        "id": "demon-slayer-s1",
        "number": 1,
        "releaseYear": 2019,
        "releaseSeason": "SPRING",
        "externalIds": {"anilistId": 101922, "anidbId": 14107, "tvdbId": 348545},
        "episodes": [
          {"absoluteNumber": 1, "airedNumber": 1},
          {"absoluteNumber": 2, "airedNumber": 2}
        ]
      }
    ],
    "movies": [
      {"id": "demon-slayer-mugen-train-film", "title": "Mugen Train", "releaseYear": 2020}
    ]
  }
}
```

A series nests `seasons`, `movies` and `specials`, each season and special
carrying its `episodes`, plus `characters`. Field names in the JSON are
camelCase (`releaseYear`, `externalIds`, `absoluteNumber`). See
[Using the dataset](/docs/using-the-dataset) for the full model.

Two things the schema offers that no response currently carries: `releaseDate`
(a `YYYY-MM-DD` string when set — a release is dated only to `releaseYear` and
`releaseSeason` today) and `externalIds.tmdbId`. `externalIds` cross-maps to
AniList, AniDB, TVDB and — for characters and staff — Wikidata. Episodes carry
numbering only: no title, no date. See [Sources and licensing](/docs/sources-and-licensing)
for the full list of what the build never fills, and why.

Titles resolve per request. Ask in the language a title was written in and you
get the native script; ask in any other and you get an English title where the
dataset has one and the romanization otherwise — so an English request answers
`Kami no Shizuku` rather than `神の雫`, readable without claiming to be an
English title. Most of the catalogue has no English title at all.

"The language a title was written in" is usually Japanese, but not always, and
the rule follows the title rather than the request: `Accept-Language: ko` on
`metal-cardbot-w` answers `메탈카드봇W`, while a Japanese reader asking for the
same series gets `Metal Cardbot W`, being no better served by Hangul than an
English reader would be.

`Accept-Language: *` returns every language instead, each under its own tag:
`en` for an English title, `ja-Latn` (or `ko-Latn`, …) for a romanization.

## Characters and cast

Characters are **global** nodes rather than children of a series, attached to
the structure through their `appearances`. `GetSeries` embeds the whole cast, so
the graph arrives with the series:

```sh
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetSeries \
  -H 'Content-Type: application/json' -d '{"id": "fate-zero"}'
```

```jsonc
{
  "series": {
    "id": "fate-zero",
    "characters": [
      {
        "id": "artoria-pendragon",
        "name": "Saber",
        "externalIds": {"wikidataId": "Q4918886"},
        "voiceActors": [
          {"staffId": "ayako-kawasumi", "language": "ja",
           "staffName": "Ayako Kawasumi", "throughout": true},
          {"staffId": "kari-wahlgren", "language": "en", "staffName": "Kari Wahlgren"}
        ],
        "appearances": [
          {"seriesId": "fate-stay-night", "seriesTitle": "Fate/stay night",
           "scope": [{"seasonId": "fate-stay-night-s1", "number": 1}], "voiceActors": [ /* … */ ]}
        ]
      }
    ]
  },
  "franchiseId": "fate"
}
```

Because a character is global, the one you reach through a series names **every**
series it appears in — that is how you learn a character is shared across the
catalogue, and each appearance carries the other series' resolved `seriesTitle`
so you can label it without another call.

If a response has no `name` or `staffName`, that is not a bug: names are filled
from Wikidata **at build time**, and the committed dataset may have been built
without the Wikidata fetch. Run `builder init` before `builder build` and the
same call returns them. Every other field is independent of it, so the graph is
usable by id either way.

### Which cast belongs where

`voiceActors` on the character is the cast that **holds throughout** — an
original-language role is nearly always the same person in every adaptation.
Cast that varies by series is not there: English dubs are routinely recast, so
each of those lives on the appearance it was cast in, optionally with a `scope`
narrowing it to specific seasons, films or specials.

You never have to combine the two yourself. An appearance's `voiceActors` is
already **the cast for that appearance** — the constant cast plus whoever is
specific to it — and a character reached through `GetSeries` has its
`voiceActors` resolved the same way for the series you asked about. Each link
repeats the staff member's resolved `staffName`, so rendering a cast list needs
no second call.

Because those lists are resolved, an actor who voices the character everywhere
appears in every one of them. `throughout` says so: it marks the credits that
came from the character rather than from the thing being described. Ignore it
and you still have the full cast; read it and you can show what a series adds
— *"Fate/Zero — also Kari Wahlgren"* — without restating Ayako Kawasumi on
every row.

Saber is the worked example: Ayako Kawasumi voices her in every Fate work and is
marked `throughout`, while Kate Higgins and Kari Wahlgren sit on the appearances
they were cast in. Asking for Fate/Zero returns Kawasumi and Wahlgren, never
Higgins.

An appearance can be narrower than a whole series. Higgins dubbed the 2006
*Fate/stay night* only, not the 2014 re-adaptation the same series id also
holds, so her appearance carries a `scope` naming that season — and Saber holds
a second appearance, for the other installments, with no English cast. An
appearance is therefore identified by its `seriesId` **and** its `scope`, and
each scope entry carries the installment's resolved `title` (plus `number` for a
season, which usually has no title of its own) so you can label it without a
second call.

Names follow the same `Accept-Language` rules as titles, via `name` and (with
`Accept-Language: *`) `localizedName`.

Only **facts** are served: ids, names, and the appearance and voice-actor graph.
Roles, biographies and images are deliberately absent; fetch those live from the
external ids.

## Localized titles

Every title-bearing node returns a single `title` string, resolved from the
request's `Accept-Language` header (default `en`). For each title, resolution
tries, in order:

1. the requested language,
2. for a non-English request, the native `original`,
3. English,
4. the native `original`,
5. any available translation.

```sh
# Japanese titles where available, else the native original → "鬼滅の刃":
curl -X POST https://anime-metadata-db.vercel.app/anime.v1.AnimeService/GetSeries \
  -H 'Content-Type: application/json' -H 'Accept-Language: ja' \
  -d '{"id": "demon-slayer"}'
```

Send `Accept-Language: *` to additionally receive the full `localizedTitle` (the
native `original` plus every translation) on every node.

> **Scope.** The API serves the structural catalog — series, seasons, films,
> specials and episodes — together with the characters and voice actors cast in
> them. Franchises group series in the dataset, and `franchiseId` is all the API
> says about that grouping today.
